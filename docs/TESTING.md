设备：Apple M5 Pro、48 GB 内存、Node v24.21.0。

素材：3000 张合成 JPEG，1800×1200 或 1200×1800，30 种图案重复。运行完整导入、预览生成、CV 和 Apple Vision 分析，并重开数据库验证。

| 指标 | 实测 |

## 外部浏览器图片验收

外部 Chrome 自动化分别验证 `127.0.0.1:4173` 同类服务地址和 `localhost`：首次加载、刷新、新会话、列表、沉浸预览、原尺寸、拼图及请求失败后重试。自动化使用隔离端口 4174；另在真实用户库的 4173 Chrome 新会话核验 15/15 个可见照片已解码，截图显示正常，不修改用户选片状态。

缺失缩略图/预览已增加原片重新生成；请求失败、原片不存在、解码失败提供状态和重试。**用户先前故障会话的根因尚未复现，不能将其标为已定位修复。** 若仍发生，需要故障页面的实际地址、失败图片请求状态和控制台错误；未关闭浏览器安全机制或开放任意跨域。Edge 尚未实际验收。

## 运行方法

```sh
npm run build:vision
npm run check
npm run test:browser
bash scripts/test.sh
npm run benchmark
```

`npm run benchmark` 在 `.local/benchmarks/<时间戳>/` 建立独立测试库，结果写入 `.local/qa/benchmark.json`；本轮列表验收数据保存在 `.local/qa/benchmark-ui.json`，截图为 `.local/qa/benchmark-library.png`。不会扫描或修改个人照片目录。

## 交付规则

功能测试通过后再独立 Git 提交并推送私有仓库。GitHub Actions 执行 Node、Swift、网页构建及浏览器检查；失败时保留合成素材产生的截图和现场信息。真实照片、SQLite 数据、缓存、导出物、API 密钥不入库。

首次 GitHub 完整浏览器运行发现新建项目期间 FileList 被清空的问题，已通过立即保留 File 对象、等待新建对话框保存完成修复。浏览器测试现在每轮建立全新的独立数据库，覆盖首次使用路径。
