当前共 **21 项 Node 自动化测试、5 条浏览器端到端流程、1 项 Swift 基础测试**。浏览器流程使用真实文件上传、数据库和导出服务；只有多模态模型响应使用本地 fixture。

截图输出到 `test-results/`，包括照片库、相似组沉浸、独立照片沉浸、拼图工作室。照片加载断言检查 `naturalWidth > 0`，不把仅存在 `<img>` 标签当成显示成功。

## 3000 张性能检查

设备：Apple M5 Pro、48 GB 内存、Node v24.21.0。

素材：3000 张合成 JPEG，1800×1200 或 1200×1800，30 种图案重复。运行完整导入、预览生成、CV 和 Apple Vision 分析，并重开数据库验证。

| 指标 | 实测 |
|---|---:|
| 第一张完成本地导入 | 15 ms |
| 3000 张全部导入 | 37.92 秒 |
| 导入及本地分析全部完成 | 42.03 秒 |
| 分析成功 / 失败 | 3000 / 0 |
| 重开数据库恢复 | 3000 张 |
| Node 服务峰值常驻内存 | 461 MB |
| 原生模型进程完成时常驻内存 | 76 MB |
| 浏览器首次显示照片库 | 1057 ms |
| 滚动到第 3000 张时实际卡片节点 | 12 |
| 浏览器异常 | 0 |

性能数据是合成素材基准，不代表高像素相机原图耗时或真实场景分组准确率。浏览器验证了滚动到底、最后照片名称和刷新恢复；没有把它当成完整帧率测试。

## 运行方法

```sh
npm run build:vision
npm run check
npm run test:browser
bash scripts/test.sh
npm run benchmark
```

`npm run benchmark` 在 `.local/benchmarks/<时间戳>/` 建立独立测试库，结果写入 `.local/qa/benchmark.json`。不会扫描或修改个人照片目录。

## 尚未验证

- 用户实际旅行照片上的相似分组质量、误分组和漏分组比例；三个默认阈值尚未在真实旅行样本上校准。
- 用户自选第三方多模态服务的权限、模型效果、费用和兼容性。尚未提供真实配置；模拟测试通过不代表真实服务联调通过。
- Windows / Linux 的完整运行体验；非 Mac 模式仅提供传统 CV 和内存密钥，不提供 Apple Vision / 钥匙串。

## 交付规则

功能测试通过后再独立 Git 提交并推送私有仓库。GitHub Actions 执行 Node、Swift、网页构建及浏览器检查；失败时保留合成素材产生的截图和现场信息。真实照片、SQLite 数据、缓存、导出物、API 密钥不入库。
