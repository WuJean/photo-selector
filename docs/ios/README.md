# 独立 iOS 版本

选片助手 iOS 使用手机自己的照片库和本地数据库，不需要电脑、Docker、R2 或网页版账号。原网页服务继续独立运行，双方不会自动同步数据。

## 使用流程

1. 首次打开点击“开始整理照片”，起名后直接选择导入来源；以后也可在“导入与选片”新建批次。
2. 从系统相册选择相册和日期范围，可全选该范围或打开网格连续选择；也可从“文件”选择多张照片或存储卡目录。
3. 粗筛为待定、保留或不要；待定和保留进入精筛，精筛只有保留／不要。沉浸式左滑下一张、右滑上一张，不显示上一张／下一张按钮；底部按钮决定，支持撤销。
4. 作品集默认只展示“我的作品”封面；精筛保留的照片在“待归集”，可复用到多个作品集。作品详情按“照片／创作”分开，编辑在顶部，标签筛选和照片墙在“更多”。首页按作品集时间展示封面和地点、诗句、描述。
5. 作品集中可搜索标签和描述，制作拼图、保存文字创作，并通过系统分享面板导出。

相册仅在授权范围内查询。仅在 iCloud 中的原片需要开启“允许 iCloud 原片下载”；不会为了后台分析自动下载未授权的云端原片。支持 JPEG、PNG、HEIC/HEIF 静态照片；Live Photo 使用静态部分。RAW 和视频不在首版导入范围内。

## 界面与引导

界面跟随系统外观：浅色使用暖白、桃色与青绿色，深色使用墨紫渐变。时间线、作品集、导入与创作使用半透明玻璃卡片；iOS 26 及以上采用系统 Liquid Glass，旧系统使用材质背景，开启“降低透明度”时提供不透明卡片。

空照片库展示插画、整理步骤和直接开始按钮；已有批次则提供“继续选片”。空批次直接展示相册与存储卡入口。沉浸式看图保持深色背景，决定按钮集中在玻璃操作区，左右滑动切图，放大后拖动平移。

## 原片保存和离线

- 相册导入默认保存 PhotoKit 引用，不重复复制原片。相册中原片被删除或撤回授权后，可能只能查看已有预览。
- 存储卡导入先生成预览，在精筛保留后复制原片到应用私有库，并校验 SHA-256。复制未完成时不能把预览当作原片导出。
- 拔卡、空间不足或复制失败后保留选片结果，可在批次菜单中重试复制；重新打开应用也会恢复待复制照片。
- 批次菜单的“重新连接来源目录”会核验已保存的文件摘要后更新目录授权。相册照片也可主动选择保存原片到本机库，下载 iCloud 原片仍需开启允许选项。
- 永远不自动删除系统相册或存储卡原片。粗筛淘汰三小时后只回收无其他引用的应用预览；前台定时或下次启动执行，iOS 后台不保证准时执行。
- 无网络可以完成本地浏览、筛选、相似分组、手工拼图和原片导出。相册源和存储卡源须实际可访问。
- 设置中可导出完整照片库至文件夹，恢复时创建新的批次和作品集，不覆盖原有记录。备份不含 API 密钥。卸载应用会删除私有库，请先备份。

## AI

默认使用 Apple 端侧 Foundation Models 的图片理解能力，实际可用性取决于系统版本、设备、模型下载状态、地区和语言。端侧不支持时会暂停分类并说明原因，基础选片功能不受影响。

设置中可以主动启用兼容 Chat Completions 的 HTTPS 服务，填写 Base URL（通常以 `/v1` 结束）、模型和自己的密钥。直接由手机访问服务，仅发送重新编码、去除 EXIF、长边不超过 1536 的 JPEG 预览。密钥保存在本机钥匙串，不包含在应用二进制、照片库备份或 Git 中。远程服务可能收费，不自动从端侧切换到远程。

粗筛入选自动进入分类队列，固定一个主体、一个景别及最多五个附加标签，并保存中文描述。标签只在设置编辑；运行任务保留启动时的标签快照。暂停或取消的任务不会自动重新派发。端侧默认并发 1，低电量和严重发热时停止新派发，回到正常状态或前台后继续。

拼图先按关键词／标签检索，随机模板和 AI 搭配都受来源和每格要求约束。视觉搭配只提交候选预览；文案复用已保存描述，缺少描述才补分析。生图关闭。

模拟器使用感知哈希分组；Apple Vision 图像特征计算须在真机上验证，不能把模拟器测试当成该模型的验收。

## 开发与构建

使用完整 Xcode 27.1 可构建 Duo 自适应和端侧多模态功能。最低部署版本 iOS 18；旧工具链可构建基础功能，但通过编译条件禁用新 SDK 专属能力。

```bash
python3 scripts/generate-ios-project.py
open ios/PhotoSelector.xcodeproj
./scripts/test-ios.sh
# 运行实际模拟器测试：
IOS_TEST_DEVICE=<simulator-uuid> ./scripts/test-ios.sh
# 只运行无需界面点击的原生测试：
IOS_NATIVE_ONLY=1 IOS_TEST_DEVICE=<simulator-uuid> ./scripts/test-ios.sh
```

项目生成只使用 Python 标准库。核心测试使用 `swift run PhotoCoreTests`；iOS 测试覆盖复制校验、备份、路径保护、拼图及模拟 AI，UI 测试只使用合成素材和隔离的测试照片库。

Duo 使用系统 ArrangementView 安排照片和控制区域，支持折叠、展开及旋转；普通设备使用紧凑／宽屏布局。实机读卡器、有限相册授权、iCloud、端侧 AI 和热状态行为需要额外真机验证。

## 免费本地真机调试

当前交付方式为 Xcode 本地开发测试，不要求购买 Apple Developer 会员，不执行 TestFlight 上传。

1. 在 Xcode → Settings → Apple Accounts 登录自己的 Apple Account。使用免费的 **Personal Team**。
2. 用数据线将 iPhone 连接到 Mac，解锁手机并完成“信任此电脑”。按 Xcode 提示，在手机“设置 → 隐私与安全性 → 开发者模式”开启并重启确认。
3. 打开 `ios/PhotoSelector.xcodeproj`，选择 `PhotoSelectorIOS` target → Signing & Capabilities，保持 Automatically manage signing，Team 选择自己的 Personal Team。
4. Scheme 选择 `PhotoSelector`，运行目标选择连接的真实 iPhone，点击 Run（Command-R）。若默认 Bundle ID 被其他团队占用，改成自己的唯一标识。
5. 首次安装若提示不受信任，在手机设置中按系统提示信任对应开发者，再打开应用。不要删除应用来刷新签名，以免丢失私有照片库。

免费签名的描述文件有效期为 7 天，到期通过同一团队、同一 Bundle ID 在 Xcode 重新构建安装。Apple 同时限制免费账号的设备和应用数量，详见 [Apple Personal Team 说明](https://developer.apple.com/help/account/basics/about-your-developer-account)。应用安装后可独立处理手机照片，日常使用不需要连接电脑；更新开发构建或刷新签名时需连接 Xcode。

为了重新生成工程后仍保留团队，可在本机创建 `ios/LocalSigning.xcconfig`，写入 `DEVELOPMENT_TEAM = 你的团队ID`。该文件被 Git 忽略，应用及测试目标均继承此设置；不保存 Apple 密码或证书私钥。未创建此文件时，模拟器和 CI 构建照常运行。

已有 `scripts/archive-ios.sh` 只供未来明确选择付费分发时手动使用，本地测试不运行此脚本，也不需要 App Store Connect。

详见 [验收记录](VALIDATION.md)。未完成的实机项目不会记为已通过。
